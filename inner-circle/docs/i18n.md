# Internationalisation (English / हिन्दी / ಕನ್ನಡ)

The prototype ships a trilingual interface. The implementation is deliberately small and has **no
runtime dependency** — it is a context provider plus JSON dictionaries.

## How it works

- `client/src/i18n/index.jsx` holds the provider, the `useT()` / `useI18n()` hooks and the loader.
- Dictionaries live in `client/src/i18n/locales/<lang>/<namespace>.json` (`en`, `hi`, `kn`).
- Files are discovered with `import.meta.glob`, so **adding a namespace never requires editing the
  loader**.
- Keys are written as `namespace.path.to.key`, e.g. `t('companion.headTitle')`.
- Interpolation uses `{{name}}`: `t('home.greeting', { name })`.
- English is the fallback for any missing key; a key missing everywhere renders as the key itself,
  so gaps are visible rather than blank.
- The chosen language is stored in `localStorage` (`ic.lang`), applied to `<html lang>`, and can be
  changed from the topbar picker or **Settings & Privacy → Language**.

## Namespaces (16)

`nav` · `common` · `moods` · `screening` · `home` · `companion` · `mood` · `assessments` · `how` ·
`play` · `breathe` · `puzzles` · `chess` · `professional` · `settings` · `register`

Parity between the three languages is enforced by a check that compares flattened key sets per
namespace. Run it with the helper script described in the contributor notes, or eyeball it before a
release: **every key must exist in all three files.**

## What is intentionally *not* translated

Two things stay in English in every language, by design:

1. **PHQ-9 and GAD-7 items and answer anchors.** These are validated instruments; using a
   non-validated translation would change what is being measured. The screening screens therefore
   show the original instrument wording, and this is disclosed on-screen via
   `screening.instrumentNote`.
2. **The fuzzy rule trace on the explainability page.** The 14 IF–THEN rule sentences are a
   technical explainability trace; they stay in English and are labelled as such
   (`how.rulesEnglishNote`). Everything around them is translated.

## Language-aware behaviour beyond the UI

- **Sentiment analysis** is Unicode-aware and carries Hindi and Kannada cue words, so emotion and
  topic signals work for Hindi/Kannada text rather than falling back to neutral. Rules of thumb and
  the lexicon are transparent by design.
- **Crisis detection** matches English, romanised transliterations, Devanagari and Kannada phrases.
  Safety must never depend on the interface language.
- **Speech**: speech-to-text and text-to-speech use the matching locale (`en-IN`, `hi-IN`,
  `kn-IN`) and the breathing guides are spoken in the chosen language.
- **Fonts**: `Noto Sans Devanagari` and `Noto Sans Kannada` are loaded as fallbacks behind Nunito
  and Fraunces so both scripts render correctly.

## Adding a language

1. Copy `locales/en/*.json` to `locales/<new>/`.
2. Translate the values; keep the keys identical.
3. Add the code and label to `LANGUAGES` in `i18n/index.jsx`.
4. Extend `SPEECH_LOCALES` in `lib/voice.js` and the crisis/emotion cue lists in `lib/sentiment.js`.

## Ethics note

Translations were produced for a student project and are **not certified translations of any
clinical instrument** (see "What is intentionally not translated"). Any real deployment in Hindi or
Kannada should be reviewed by fluent speakers of the target community and, for anything that
touches measurement or safety, by the relevant clinicians.
